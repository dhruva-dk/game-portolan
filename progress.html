Agent protocol (read first)

  1. Read this page top to bottom, then PROMPT.md in full. PROMPT.md is the spec; every line of it is required. Nothing here may weaken it.
  2. Pick the work package (WP) you were assigned in Work packages. Check its dependencies are done. Set its status line to Status: in progress (YYYY-MM-DD).
  3. Touch only the files your WP owns, plus the append-only registration lines in the shared files. Another agent may be working in the same checkout: re-read a shared file immediately before editing it, never reformat files you do not own, and stage only your own paths (git add <paths>, never git add -A).
  4. Legacy code from the earlier game is reference material only. It is deleted from the tree in WP1; read it with git show 6ce29f2:src/<file>.ts (see Code audit for what is worth adapting). Never re-add src/assets/ or any image, model, font or audio file.
  5. Before finishing: npm run typecheck, npm test, and the checks/captures named in your WP's definition of done; the console must be free of errors and warnings. Save your evidence as progress/shots/wpNN-*.png (before and after where relevant).
  6. Update this page: your WP status (done (date) with a one-line result), the spec status rows you advanced, acceptance check results, captures, a dated log entry with before/after screenshots, and what comes next. Keep every section's id stable; edit with text tools; keep one table row per line.
  7. Commit on main with message WPnn: <title> and the trailer line Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>. List any new library in CREDITS.md with source and licence.
  8. Code standard (PROMPT.md "How to work"): every line earns its place; no dead code, duplication, speculative features or placeholder art left behind; create files only when needed; prefer the carefully built procedural solution over the shortcut.
  9. Art direction from the user (2026-10-24): the environment must be more realistic and far richer in detail than the first terrain/sea passes, while keeping the drawn aesthetic. Think of a master engraver/illustrator who draws from life: believable geology and proportions (eroded headlands, gullies, crags, boulders, scree, pebbled and sandy beaches, cliff strata with fissures, varied silhouettes rather than uniform mesas), believable water (dense, varied wave strokes, swell, reflections, foam patterns), dense believable vegetation, and many layers of fine detail at every distance — all expressed through ink line, hatching and transparent watercolour, never photoreal PBR. Every render package and every review applies this.
  10. Shared working copy: never rebuild or revert progress.html (or any shared file) from HEAD — that drops other agents' uncommitted edits. Edit only your own lines with targeted replacements, re-reading them first. Keep scratch files in a subdirectory of the scratchpad unique to your package (e.g. scratchpad/wp16a/).

A2. Determinism specification

  • Why: the iOS app runs in WKWebView (JavaScriptCore). JSC and V8 both give IEEE-754 round-to-nearest results for + − × ÷, Math.sqrt, Math.fround, integer/bit ops — and JS never fuses multiply-adds — but Math.sin/cos/tan/asin/acos/atan/atan2/exp/log/pow/cbrt/hypot/sinh/… are implementation-defined and differ between engines (and even between V8 versions and constant-folded vs runtime paths, notably **).
  • Allowed in sim/career: + − × ÷ %, comparisons, bit ops, Math.sqrt abs floor ceil round trunc sign min max imul clz32 fround, typed arrays, plain arrays and plain objects with fixed shapes.
  • Banned in sim/career (enforced by tests/sim/purity.test.ts): every transcendental Math.*, Math.random, the ** operator, Date, performance, timers, async/promises inside a step, Intl/toLocale*/localeCompare, for…in, Object.keys/values/entries on map-like objects, Map/Set in state, Array.prototype.sort without a total-order comparator (ties broken by id), string-formatted floats in hashes, any global (navigator, location, window), and imports of three/DOM/render/ui/audio.
  • Deterministic math (src/sim/math.ts): dsin dcos dtan (Cody–Waite reduction by π/2 with a two-constant split, then polynomials), datan datan2 dasin dacos (argument halving + series, as legacy), dexp (x = k·ln2 + r, polynomial, exact power-of-two scaling built from bits), dlog (exponent/mantissa split via DataView bits, atanh series), dpow only where unavoidable (prefer repeated multiplication). Target absolute error ≤ 1e-12 on game ranges; outputs are pure functions of input bits. Unit tests measure error against Math.* in Node. Built (WP1): Taylor kernels truncated below 1e-17 (sin/cos on |r| ≤ π/4, exp on |r| ≤ ln2/2), atan by two halvings and its series to t^21, log by the atanh series to s^19, 2^k from an exactly built table; worst measured error 1.1e-16 (sin, cos) to 8.9e-16 (atan2, acos), table in the WP1 log. dsin/dcos/dtan are fully accurate for |x| ≤ TRIG_RANGE = 2^20·π/2 ≈ 1.6e6 and deterministic beyond. No dpow: nothing needs it yet.
  • RNG: sfc32 seeded via splitmix32, state = four uint32 held in the match state. Named streams so systems do not perturb each other: world events, weather, loot, storm, and one per captain. Streams derived as hash32(matchSeed, streamId).
  • Order: every loop over ships/entities runs in index order; entity arrays are append-in-order with tombstones compacted deterministically; no iteration over hash maps.
  • Cross-engine proof: a determinism-vector test (fixed input set → hash of every d* output and of a 2-minute seeded match) runs in Node, Chromium and Playwright WebKit (JavaScriptCore — the closest proxy for WKWebView), and the iOS Simulator run in check 8 logs the same hashes. Any mismatch is a blocker.

A3. Match state, serialisation, hashing, inputs, replay

  • MatchState (src/sim/state.ts) is one plain-data object graph: header (format version, seed, tick, RNG streams), environment (wind phase, weather cells, tide phase, floe angles, storm phase/timers, caldera timer, hour), ships[10] (pose and previous pose, speed, turn, sail setting, hull, fire, list, fittings[6] {kind, tier}, consumables[3] {kind, count}, purse, bank, gull state, effect timers, trail cell list, home info, alive, sink order), territory owner and trailOwner (Uint8Array(6·512²)), entities (projectiles, coins, chests, finds, kegs, shells), captain minds (all AI memory as numbers), stats and the timeline log. No closures, class instances with hidden fields, Maps or Sets. WP1: the shape is declared once as codec schemas in state.ts (kinds f64, int, bool, bytes(n), words(n), list(kind, n?), rec(...fields)); the TypeScript type, the encoding and the hash all follow, so no field can be hashed but not saved. The skeleton holds seed, tick, the STREAM generators (world, weather, loot, storm, captains 1–9), the ten ships' controls (sail, course) and the owner/trail maps (0 nobody, else ship + 1). Each sim WP adds its fields and bumps MATCH_FORMAT.version.
  • Codec (src/sim/codec.ts): versioned little-endian binary writer/reader (Float64 for reals, varints for ints, RLE for the territory arrays). encode(state) → bytes; decode(bytes) → state; hashState(state) = 64-bit two-lane hash over encode(state). Because save/resume uses exactly the hashed bytes, the test "for random k: decode(encode(state at k)), run to the end → same final hash as uninterrupted" proves the snapshot is complete. Snapshot size target ≤ 300 KB. WP1: encodeMatch, decodeMatch, matchHash (16 hex digits); decode refuses foreign, outdated, truncated or corrupt bytes; a NaN or ∞ in a real throws on encode, and −0 in an int is stored as 0. A synthetic late-match state is 26.8 KB and encodes or hashes in under 3 ms.
  • ShipInput (src/sim/input.ts), one per ship per tick, integers only: steer int8 (−127…127), sail −1/0/+1 step, flags bitfield (breakOff, headHome held, callGull, useAimed, dive, …), consumable slot or −1, aim target as a territory cell index or −1 (auto-aim), chestPick 0–2 or −1, course (list of cell indices; set/cleared as an event). The UI quantises touch to this struct; captains emit the same struct from inside the step. WP1: ShipInput {steer, sail, flags, consumable, aim, chestPick, course} with course = cells, [] to drop it, or null for no change; FLAG {breakOff, headHome, callGull, useAimed, dive}; applyControls keeps the sail setting and the course on the ship.
  • Recording: the player's inputs as change events (tick, field, value), compact JSON; replay reconstructs the identical per-tick struct. Recordings are test data (in tests/), never game assets. WP1: {format: 1, events: [tick, field, value][]}; recorder()/record() (validating), parseRecording() (untrusted JSON, checked and copied), replay()/inputAt() (from any tick). The runner is in src/sim/match.ts: step(state, playerInput) and runMatch(state, recording, tick), which stops at a tick until WP8 gives the match an end.
  • Pause (chart open) = the loop stops stepping; the sim never sees wall time. Background → snapshot to IndexedDB on visibilitychange/Capacitor App pause; resume decodes and continues from that tick.
  • Results: the step emits a MatchResult when one ship remains: finish order, sea claimed, sinkings, treasure (share of bank × position multiplier), timeline (break-off, loops closed, trails lost, chests chosen, fights, sinking/win), and the observed player-style metrics the career needs.

A4. Career state model

  • CareerState (src/career/state.ts), plain JSON-able, integers only (fixed-point per-mille for learned weights): version, career seed, match index, player {rank points, tier reached (never lost), treasure, unlocked forms, selected form, gull {talons, wings, eye, beak, dive levels; plumage marks list (trait, level, tier pigment)}, style profile (break-off region histogram, loop-size mean, raid rate, run-hull threshold, fitting preferences, storm handling — each a decayed fixed-point average)}, captains[30] {rank points, tier, form, start-fitting tier, gull levels, learned counter-weights per habit with fade, record vs player (met, sunk by player, sank player), grudge flag}, career chart {seen-cell bitset on a coarse cube grid, discovered loot sites, regions named bitmask}, first-voyage flag, recent results for cards.
  • Pure functions: matchSetup(career, seed) → opponents (nine nearest rank; for the first voyage the nine lowest at gentlest), their forms/fittings/gulls/learned counters, player's form/gull; careerAfterMatch(career, result) → new career (rank points from position + sea + sinkings, treasure, unlocks, profile update with fade, captain learning for those who shared the match, grudges, chart discoveries); leagueRound(career) resolves captains' own results from Rng(hash(careerSeed, matchIndex)).
  • Hash: canonical binary encoding with a fixed field order (never JSON.stringify key order). Settings (sound, music, haptics, reduced motion) are stored separately and excluded from the career hash.
  • Saving: career after every match and the match snapshot on background, both in IndexedDB (src/app/save.ts); a corrupt or version-mismatched snapshot is discarded, never half-loaded.

A7. World data

  • Same world every match and career. regions.ts is a hand-authored table; geography.ts builds every field from it deterministically (d* math) so the sim (collision, depth, kelp, tide passages) and the renderer (meshes, textures) share exactly one geography.
  • Placement (proposal; WP3 may refine with reasons): north pole Ice Crown; upper ring (lat +26.57°) at lon 0/72/144/216/288: Fjords, Basalt Stacks, Kelp Shallows, Amber Shoals, Weeping Isle; lower ring (lat −26.57°) at lon 36/108/180/252/324: Glass Sea, Fire Archipelago, Mangrove Labyrinth, Coral Atolls, Spice Isles; south pole Maelstrom. Each region's Voronoi cell is one face of the dual dodecahedron (equal areas, which also makes check 4's "final calm per region" uniform by symmetry).
  • Per region (data): id, name, vertex index; local frame (north/east tangent); pigments (land, shallows, foliage, accent, ink tint); climate and flora species; landforms as strokes in region-local coordinates (bearing, distance in u; kinds: island body capsule, ridge, cliff headland, spit, bay carve, reef ring with channel gaps, stack/column field, arch, sandbar/tidal flat with height band, cone/caldera, ice-floe field, kelp bed polygon, mangrove channel network, hot-water zone, whirlpool); the landmark (kind, position, perk id, chart symbol); harbours (≥ 1: position, facing, moorings, repair zone); lighthouses (headland position, facing, beam period); fauna habitats (species, area, count); weather tendencies (fair/fog/squall/calm weights); loot richness and fixed find sites (wrecks, caches); mechanics parameters (floe rotation rate, tide period/passages, kelp slow and hide, hot-water damage, vortex strength, channel widths); music mode and motif.
  • Open sea data: fixed current lanes between region pairs (great-circle arcs with width and speed); Great Current route generator (seed picks a smooth path through several regions); open-sea find richness.
  • Generated fields on the cube-sphere (same equal-angle mapping as territory): height (Float32 6·512²), signed coast distance, floor type (sand, rock, coral, kelp, ice, mud, black sand), region id, nav grid (6·64², passable/cost, tide-dependent cells flagged). Dynamic geography (tide level, floe positions) is evaluated in the sim on top of the static fields.
  • WP3: the nav grid is 6·128² (2.5 u cells), not 64², so the narrowest designed channels (7–8 u) stay connected; each nav cell and edge carries the sea level above which it opens, so routes follow the tide. Built in 0.88 s (fields) + 0.26 s (nav) on the dev Mac.
  • Startup: generation runs in a Web Worker; a 128²/face level for the title, full 512² while the title and harbour show; cached in IndexedDB keyed by a hash of the region data (runtime cache, not a shipped file).

A8. Rendering approach (the illustrated style on a sphere)

  • Frame graph (WebGL2): (1) scene pass at dynamic resolution into two targets: colour (washes + hatching computed in materials, authored in display space — no HDR, no tone mapping, no bloom) and a normal/depth/object-class target; (2) one full-screen ink composite: silhouette and crease lines from depth/normal/class discontinuities (silhouettes 1.5–2.5 px swelling with nearness, creases ≤ 1 px, both fading with distance so the horizon stays delicate; line wobble from world-anchored noise), wash pooling (darkening near edges), the deckle (darker tone at the frame edge — the only screen-anchored effect), and per-hour grade from the palette; (3) UI in an orthographic pass. No MSAA; lines carry their own coverage. Half-float targets only (iOS lacks float32 colour buffers). Built (WP2): the scene pass writes an RGBA8 colour target (display sRGB; alpha is the veil that lets fog and smoke hide the ink beneath) and an RGBA8 aux target (octahedral view normal, ink id, ink weight) over a 24-bit depth texture; an edge pass turns silhouettes, folds, creases and material boundaries into line elements (darkness, half-width, boundary normal, centring offset) and the composite gathers them within 3 px into anti-aliased ink: 16 B/px, 91 MB of targets at the largest iPad at scale 1. Widths are in CSS px (silhouettes 1.4, creases 0.65), swell to 1.5× on the side turned from the light and thin to 0.4× on the lit side (lost and found edges), and thin and lighten over the view's fade distances. The per-hour look lives in the materials (paper, ink, shade and sun glazes per hour); the composite applies only the deckle and the storm grade. No 8-bit target needed more precision.
  • Paper anchored to the world: every material calls paper(p) from style/glsl.ts: fibre and grain from generated tileable textures sampled in the planet frame (sea, terrain), the object frame (ships, props), or by direction (sky). Grain octave chosen by log₂(camera distance) and cross-faded, so grain size is stable on screen yet never slides; foxing and stains are low-frequency and planet-anchored, so the chart and the globe share the same stains. Built (WP2): the octave is chosen per pixel from the anchor frame's footprint (so grazing views coarsen instead of aliasing) to keep a tile at 280 CSS px; proven by tests/style/gallery.test.ts (grain correlation 0.96 at the same world points after a camera turn, ≈ 0 at the same pixels).
  • Hatching: tonal art maps generated at startup (6 tones × stroke-preserving mips, 256²), sampled in surface-aligned coordinates (island-local triplanar with direction following the slope; ship planking UVs; cloud billboards), parallel hatching deepening to cross-hatching as N·L and occlusion fall. Shadow is drawn, never darkened. Decision (WP2): no tonal-art-map textures. Hatching is procedural: three stroke families (along the form, 70° across, diagonal) whose spacing nests by octaves — every second stroke of one octave is a stroke of the next, so strokes are preserved as they thin with distance, exactly the TAM property — with continuous tone as stroke width, per-stroke jitter, wobble, breaks and tapered ends keyed to each stroke's world position. Crisper at every distance than a 256² texture, no texture memory, no ghosting between tone levels. Strokes follow the form through hatch coordinates: cross-contours of an axis (terrain, rocks, towers, hulls) or the geometry's uv (spheres, sails, planking).
  • Watercolour: flat pigment washes mixed subtractively over paper; darker pooling at wash edges (from distance fields where available — coast, territory border — and the composite edge pass elsewhere); granulation (world-anchored noise) in deeper washes; soft bleed via noise-warped boundaries.
  • Pigments: only the illuminator's palette (iron-gall black, sepia, umber, ochre, verdigris, malachite, ultramarine, indigo, vermilion, rose madder, lead white, gold leaf) plus the captains' named pigments derived from them. Gold leaf is the only view-dependent shine.
  • Sea mesh: a camera-centred geodesic disc (polar grid, geometric radial spacing, reaching past the horizon) positioned on the sphere in the vertex shader — one draw call, no seams or pinching anywhere including the poles. Depth wash and coastline rings come from the geography textures; wave pen strokes are procedural in the fragment shader on a world-anchored jittered grid, oriented by the wind; foam from coast distance and the wake buffer. Territory washes are composited inside the sea shader (chunk owned by WP20).
  • Terrain: island patches built once from the height field (quadtree LOD from legacy terrain.ts), never crossing the chart net's cut edges (they lie in open sea by construction).
  • Deck → chart (one unbroken zoom). A single parameter z ∈ [0, 1] drives camera and morph. z 0→0.5: the camera lifts from chase to orbit; ships shrink to silhouettes, relief eases to chart relief. At orbit the world is drawn as the chart globe: twelve pentagonal sheets, one per region — the dodecahedron dual to the region icosahedron, so every region sits at the centre of its own sheet and every cut edge runs through open sea halfway between regions (≥ 40 u from any coast). Swapping the sea disc for the chart globe happens where both render identically, so there is no visible cut. z 0.5→1: each sheet flattens (sphere → gnomonic plane) and the sheets unfold about their hinges along a spanning tree (two "flowers" of 1 + 5 sheets joined at one edge), coming to rest flat on parchment like printed globe gores; per-sheet transforms are 12 uniforms. On the chart: a wind rose at each region with its 16-rhumb network (black winds, green half-winds, red quarter-winds), region names in calligraphy, coastlines in ink, territory washes, ships as inked silhouettes with heading arrows, the storm as a bruise of wet ink. In a match the net is laid out with the player's current region at the centre of a flower, so local courses never cross a cut; the career chart uses the fixed Ice-Crown/Maelstrom layout. Decision record: a single whole-world projection (Hammer/Aitoff) was rejected because the far-side regions (and, centred on a region, its antipodal region) would be smeared along the rim; the dodecahedral net keeps all twelve regions undistorted (gnomonic scale error ≤ ~1.25 at sheet corners) and literally unrolls. If the review judges the net unreadable as a portolan, revisit here.
  • Pause freeze: world animations read a render clock that stops while the chart is open (spray hangs, smoke stops, gull wings stay spread); only the zoom has its own clock.
  • Night: per-hour palette table (dawn, morning, midday, afternoon, golden hour, dusk, blue hour, night, pre-dawn) interpolated by hour; night swaps light hatching for silver-ink highlights, lights are painted glow washes, beams are hatched rotating cones. Lighting is computed in the player's local frame from the global match hour.
